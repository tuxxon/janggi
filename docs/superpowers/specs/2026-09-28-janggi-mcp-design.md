# 장기 — 실행 가능 앱 + MCP 대국 + 기보 복기 설계

날짜: 2026-09-28 · 상태: 설계 (구현 전)

## 1. 목표

1. `Janggi.jsx`(단일 파일, 프로젝트 없음)를 `npm start` 한 번으로 실행되는 앱으로 만든다.
2. MCP로 Claude(Claude Code 등)나 ChatGPT(개발자 모드 커넥터)가 **실제로 수를 둔다**.
3. 모든 대국을 **기보 파일**로 저장하고, 화면과 MCP 양쪽에서 **복기**할 수 있다.

성공 기준:
- `npm start` 후 `http://localhost:8787`에서 대국이 된다.
- 헤드리스 `claude -p`가 MCP 도구만으로 엔진과 여러 수를 둔다(실측).
- 서버를 재시작해도 진행 중인 판이 이어지고, 지난 판을 한 수씩 되감아 볼 수 있다.

## 2. 범위 밖 (원본에 없던 규칙은 추가하지 않는다)

- 빅장, 점수(계가) 판정, 무승부/반복 규칙 — 원본처럼 외통수로만 승부.
- 여러 판 동시 진행 — 서버에는 진행 중인 판이 항상 하나.
- 인증 — 터널 URL을 아는 사람은 누구나 수를 둘 수 있다(게임 데이터뿐).

## 3. 구조: 서버가 판을 가진다

```
브라우저(React) ──REST(사람 수)──▶ ┐
       ▲                           │   Node 서버 (127.0.0.1:8787)
       └──SSE(상태 푸시)────────── ┤   ├─ Game (진행 중인 판 하나)
Claude Code ──HTTP /mcp──────────▶ ┤   ├─ 엔진 자동 응수
ChatGPT ─cloudflared 터널─▶ /mcp ─▶ ┘   └─ games/*.json (기보)
```

진실은 서버의 판 하나뿐이다. 브라우저는 판을 그리기만 하는 뷰라서, 탭이 없어도 에이전트끼리 또는 에이전트와 엔진이 둘 수 있다.

기각한 안:
- **브라우저가 판을 가짐**: 탭이 열려 있어야만 AI가 둘 수 있고, 새로고침하면 판이 깨진다.
- **stdio MCP**: ChatGPT가 쓸 수 없다.

## 4. 좌표와 표기

- 칸: 파일 `a`–`i`(열 0–8), 랭크 `1`–`10`. 초(아래) 쪽 궁 줄이 랭크 1이다.
  - 내부 인덱스 `i = r*9 + c`에서 칸 이름은 `'abcdefghi'[c] + (10 - r)`.
  - 예: 초 왼쪽 차 `(9,0)` = `a1`, 초 궁 `(8,4)` = `e2`, 한 궁 `(1,4)` = `e9`.
- 수: 출발 칸과 도착 칸을 붙여 쓴다(`b1c3`, `e4e5`, `a10a9`). 한 수 쉬기는 `pass`.
- 기물 글자: 초는 대문자, 한은 소문자. `K`궁 `R`차 `C`포 `H`마 `E`상 `A`사 `P`졸/병.

## 5. 게임 상태 기계 (`server/game.js`)

- **편마다 컨트롤러**: 초·한 각각 `human | engine | agent`.
  - `human`: 브라우저 클릭/드래그로 둔다.
  - `engine`: 서버가 420ms 뒤 `bestMove(level)`로 자동으로 둔다. 원본의 지연을 유지한다.
  - `agent`: MCP `make_move`로 둔다.
- **수가 반영된 뒤의 전이**: 지금 React의 `step()`을 서버로 옮긴다.
  - 둘 수 없고 장군이면 외통수로 끝난다.
  - 둘 수 없지만 장군이 아니면 자동으로 쉬고 차례가 넘어간다.
  - 장군이면 메시지를 낸다.
  - 메시지의 말투는 원본을 따르되, 컨트롤러 조합에 맞게 일반화한다. 예: "외통수! 초(파랑) 승리".
- **쉬기**: 장군 상태가 아닐 때만 할 수 있다(원본 규칙).
- **무르기**: 브라우저에서만 할 수 있다.
  - 사람이 둘 차례인 국면이 나올 때까지 수를 되돌린다(최소 한 수). 원본의 "내 수와 AI 응수를 같이 무름"을 일반화한 것이다.
  - 사람 편이 없으면 무르기는 비활성이다.
  - 대기 중인 엔진 타이머는 취소한다.
- **`waitForTurn(side, ms)`**: 판이 바뀔 때마다 조건을 다시 본다. 그 편 차례가 오거나, 판이 끝나거나, 시간이 넘으면 끝나고, 결과에 `timedOut` 여부를 싣는다.
- **엔진 탐색 부하**: 엔진은 메인 스레드에서 동기로 돈다(원본 브라우저와 같음). 난이도 4에서 몇 초 동안 서버가 멈출 수 있다는 걸 받아들인다.

## 6. 기보 저장과 복원 (`server/store.js`, `src/record.js`)

한 판에 파일 하나. 경로는 `games/<id>.json`이고, id는 시작 시각에 밀리초까지 붙인 것이다(예: `2026-09-28T14-03-12-345`). `games/`는 git에서 제외한다.

```json
{
  "id": "2026-09-28T14-03-12-345",
  "createdAt": "2026-09-28T14:03:12.345Z",
  "setups": { "c": "마상마상", "h": "상마상마" },
  "controllers": { "c": "human", "h": "agent" },
  "level": 3,
  "moves": ["b1c3", "h10g8", "pass"],
  "result": null
}
```

`result`는 끝난 판이면 `{ "winner": "c", "reason": "외통수" }` 같은 값이 들어간다.

- **정본은 수순이다.** 국면은 저장하지 않고, 초기 배치에서 `replay()`로 재구성한다.
  - 엔진이 둔 수도 수순에 기록되므로, 재생할 때 엔진을 다시 돌리지 않는다. 그래서 무작위성이 없다.
  - 둘 수 없어서 생기는 자동 쉬기는 국면이 결정하므로, 재생하면 똑같이 다시 나온다. 수순에는 넣지 않는다.
- **쓰기**
  - 수가 반영될 때마다 임시 파일에 쓰고 rename 한다. 쓰다가 죽어도 파일이 반쯤 깨지지 않는다.
  - **파일 쓰기가 실패하면 그 수는 반영하지 않고 에러를 돌려준다.** 메모리와 파일이 어긋나지 않게 하기 위해서다.
- **무르기**: 무른 수는 수순에서 잘라낸다.
- **서버 시작 시**
  - 가장 최근 파일을 불러와 재생하고 그 판을 이어간다. 끝난 판이면 최종 국면을 보여준다. 파일이 하나도 없으면 새 판을 시작한다.
  - 재생하다가 불법 수가 나오면(파일 깨짐) 조용히 넘어가지 않는다. 로그에 크게 남기고 새 판을 시작하며, 깨진 파일은 지우지 않는다.
- **id 검증**: API로 들어온 id는 `^[0-9T-]+$`로 검사해서 경로 탈출(`../`)을 막는다.

## 7. 복기

### 화면

- "기보" 버튼을 누르면 저장된 판 목록이 최신순으로 나온다. 각 줄에는 날짜·시각, 초와 한의 컨트롤러, 수 수, 결과(승자 또는 진행 중)가 보인다.
- 한 판을 고르면 **복기 모드**로 들어간다.
  - 판은 읽기 전용이다. k수째 국면을 보여주고, 직전 수를 강조한다.
  - 조작: `⏮ ◀ ▶ ⏭` 버튼, 번호가 붙은 수순 목록(클릭하면 그 수로 이동), 키보드 `←` `→`.
  - 판 방향은 그 판의 컨트롤러 기준으로 정한다(아래 8절 규칙과 같음).
  - "대국으로 돌아가기" 버튼으로 나온다. 진행 중인 판도 목록에 있어서 복기할 수 있다.
- 국면은 브라우저가 `src/record.js`의 `replay()`로 직접 계산한다. 서버는 기보 JSON만 준다.

### MCP

- `list_games`: 저장된 판 목록.
- `get_game {id, move?}`: 번호 붙은 수순과, `move`수째 국면의 ASCII 판(`move`를 생략하면 마지막 국면). 에이전트가 "방금 판 복기해줘"에 답할 수 있게 하려는 것이다.

## 8. 화면 변경 (`src/Janggi.jsx`)

- 기존 렌더링과 조작(탭, 드래그, 슬라이드 애니메이션, 잡은 기물 트레이)은 그대로 둔다.
- 사람 편의 차례일 때만 입력을 받는다. 입력은 REST로 보낸다.
- 설정의 "AI가 둘 편"을 **초 / 한 각각 사람·엔진·AI 에이전트** 드롭다운으로 바꾼다. 난이도와 상차림 설정은 유지하고, 새 게임을 누를 때 적용된다(원본과 같음).
- 판 방향: 한이 사람이고 초가 사람이 아니면 뒤집는다.
- 상태 문구:
  - 엔진 차례: "엔진이 생각하는 중…"
  - 에이전트 차례: "AI 에이전트(MCP) 차례를 기다리는 중…"
- SSE가 끊기면 EventSource의 자동 재연결에 맡기고, 재연결되면 전체 상태를 다시 받는다.

## 9. REST / SSE

| 메서드 경로 | 용도 |
|---|---|
| `GET /api/state` | 현재 판 전체 상태 |
| `GET /api/events` | SSE. 판이 바뀔 때마다 전체 상태를 보낸다 |
| `POST /api/move {from,to}` | 사람 수. 차례인 편이 `human`이 아니면 거부 |
| `POST /api/pass` | 사람의 쉬기 |
| `POST /api/undo` | 무르기 |
| `POST /api/new {cho,han,level,choSetup,hanSetup}` | 새 판 |
| `GET /api/games` | 기보 목록 |
| `GET /api/games/:id` | 기보 하나 |

상태 페이로드: `{id, b, turn, controllers, level, setups, last, caps, over, msg, moves, canUndo, engineThinking}`

## 10. MCP 도구 (`/mcp`, Streamable HTTP, stateless)

| 도구 | 입력 | 동작 |
|---|---|---|
| `get_state` | — | ASCII 판, 차례, 편별 컨트롤러, 직전 수, 장군/외통수, 잡은 기물, 번호 붙은 수순, **차례인 편이 둘 수 있는 수 전체**(기물별로 묶음) |
| `new_game` | `cho, han`(각 `human\|engine\|agent`), `level?`, `cho_setup?`, `han_setup?` | 새 판을 시작하고 새 기보 파일을 만든다 |
| `make_move` | `side`(`cho\|han`), `move`(`b1c3` 또는 `pass`) | 검증 후 둔다. 그다음 **상대가 응수할 때까지 최대 25초 기다려** 결과 상태를 돌려준다 |
| `wait_for_turn` | `side`, `timeout_sec?`(기본 25, 최대 55) | 내 차례가 오거나 판이 끝날 때까지 기다린다 |
| `list_games` | — | 7절 |
| `get_game` | `id`, `move?` | 7절 |

- `make_move`는 이럴 때 거부한다(`isError`와 이유, 그리고 둘 수 있는 수 목록을 같이 돌려준다):
  - `side`의 차례가 아닐 때
  - 그 편이 `agent`가 아닐 때
  - 둘 수 없는 수일 때
  - 장군 상태에서 쉬려고 할 때
- `side`는 Claude 대 ChatGPT처럼 에이전트 둘이 둘 때 서로의 편을 두지 않게 막는 장치다. 협조적인 클라이언트를 전제로 한다(인증 아님).
- `get_state` 출력 예:

```
장기 · 12수째 · 차례: 한(빨강) [agent]
초(파랑)=human  한(빨강)=agent  난이도 3
직전 수: 초 b1c3 (마)   상태: 장군!

     a  b  c  d  e  f  g  h  i
 10  r  h  e  a  .  a  e  h  r
  9  .  .  .  .  k  .  .  .  .
 …
  1  R  .  E  A  .  A  E  H  R
(대문자=초, 소문자=한 · K궁 R차 C포 H마 E상 A사 P졸/병)

둘 수 있는 수 (한):
  차 a10: a9 a8 a7 …
  마 h10: g8 i8
  …  또는 pass
수순: 1. 초 b1c3  2. 한 h10g8  3. 초 (둘 수 없어 쉼) …
```

## 11. 보안

- `127.0.0.1`에만 바인드한다. CORS 헤더는 없다.
- **Host 헤더 검사**: `localhost`, `127.0.0.1`, `*.trycloudflare.com`만 허용한다. 악성 웹페이지가 DNS rebinding으로 로컬 서버를 조작하는 걸 막는다.
- 기보 id 형식을 검사한다(6절).
- 터널을 열면 URL을 아는 누구나 둘 수 있다. 터널은 사용자가 `npm run tunnel`로 직접 열 때만 열린다.

## 12. 테스트 (TDD)

- **vitest 단위 테스트**
  - `notation`: 칸과 수 변환을 리터럴 값으로 확인한다(`a1`↔81, `e2`↔76, `e9`↔13 등).
  - `game`:
    - 불법 수, 차례가 아닌 편, 컨트롤러 불일치를 거부하는지
    - 외통수, 자동 쉬기, 장군 중 쉬기 거부
    - 무르기 일반화
    - 엔진 자동 응수
    - `waitForTurn`이 끝나는 조건과 타임아웃
  - `record`/`store`:
    - 저장 → 새 인스턴스 → 복원했을 때 같은 국면이 되는지(자동 쉬기 포함)
    - 쓰기 실패 시 수를 거부하는지
    - 깨진 파일이면 새 판을 시작하고 파일은 남기는지
    - id 경로 탈출을 거부하는지
- **엔진 규칙 대조**: Fairy-Stockfish WASM(`ffish`, dev 의존성)과 여러 상차림·국면에서 perft 수를 대조한다.
  - 대조 수치는 리터럴로 테스트에 박는다.
  - 원본 엔진과 불일치가 나오면 **고치기 전에 사용자에게 보고**한다(원본 엔진이 규칙을 틀렸을 수도 있기 때문).
- **MCP 통합 테스트**: SDK 클라이언트로 HTTP 서버(임시 포트, 임시 `games/`)에 붙어 6개 도구를 전부 호출한다.
- **Playwright**
  - 클릭으로 수를 두면 서버 상태가 바뀌는지
  - MCP로 둔 수가 SSE를 타고 화면에 나오는지
  - 복기 모드에서 이동이 되는지
  - 스크린샷을 눈으로 확인한다.
- **실측 E2E**: 헤드리스 `claude -p --mcp-config .mcp.json`이 엔진을 상대로 여러 수를 둔다.
- **리뷰**: Codex(`gpt-6-astra` xhigh) 적대적 리뷰를 돌려서 HIGH/MED를 고친다.

## 13. 열린 결정 (이 설계에 포함하지 않음)
