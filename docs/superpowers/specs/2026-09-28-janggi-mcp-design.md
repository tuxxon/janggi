# 장기 — 웹앱(Pages) + 승률 분석 + 기보 복기, 그리고 GCF MCP 대국 설계

날짜: 2026-09-28 · 개정 2.1 (신경망 배달: 기본 평가 + 사용자가 넣기)

## 0. 결정 기록

| 결정 | 내용 |
|---|---|
| 대국 구성 | 편마다 사람 / 엔진 / AI 에이전트 |
| 기보 | 파일로 저장하고 복기할 수 있다. 정본은 수순 |
| 승률 | Fairy-Stockfish로 네 가지를 보여준다: 대국 중 막대, 수마다 변화와 실수 표시, 복기 그래프, 후보 수 토글 |

## 1. 단계

**1단계 — Pages 정적 웹앱** (이 문서에서 자세히 다룬다)
- 사람 대 사람, 사람 대 엔진, 엔진 대 엔진 대국
- 브라우저 안의 Fairy-Stockfish WASM으로 승률 분석
- 기보는 브라우저에 저장하고, 파일로 내보내고 가져올 수 있다. 복기 화면 포함
- 배포 주소는 `touchizen.com/janggi/`

**2단계 — GCF MCP 대국** (12절 개요만. 1단계가 끝난 뒤 상세 spec을 따로 쓴다)
- Claude와 ChatGPT가 고정 URL MCP로 두고, 판마다 코드로 구분한다.
- Firestore에 저장하고 실시간으로 동기화한다.

1단계 성공 기준:
- `npm run dev`로 로컬에서 대국, 승률, 복기가 된다. Playwright와 눈으로 확인한다.
- 실제 Chromium에서 `crossOriginIsolated === true`이고, 신경망으로 분석된 승률이 뜬다.
- Pages 배포본에서도 같은 것이 된다.

## 2. 범위 밖

원본에 없던 규칙은 추가하지 않는다:
- 빅장, 계가, 무승부/반복 규칙 — 원본처럼 외통수로만 승부.
- 승률 보정 — 평가 점수를 승률로 바꿀 때 체스용 식을 그대로 쓴다(7절).
- 1단계에서 AI 에이전트(MCP) — 2단계에서 한다.
- Fairy-Stockfish를 대국 상대로 쓰는 것 — 분석 전용이다.

## 3. 구조 (1단계)

```
touchizen.com/janggi/  (GitHub Pages, 정적)
 ├─ React 앱 ── src/game.js (상태 기계, 순수 함수) ── src/engine.js (원본 규칙·탐색)
 │     │
 │     ├─ src/analysis/ ── Fairy-Stockfish WASM (pthread, 자체 워커)
 │     │                    └─ NNUE: Google Drive에서 직접 받기 → Cache Storage
 │     └─ src/storage.js ── localStorage (기보) + JSON 내보내기/가져오기
 └─ coi-serviceworker.js ── COOP/COEP를 붙여 SharedArrayBuffer를 연다
```

`src/game.js`는 I/O가 없는 순수 모듈이다. 2단계 GCF가 **같은 파일을 그대로** 써서 수를 검증한다.

## 4. 좌표와 표기

- 칸: 파일 `a`–`i`(열 0–8), 랭크 `1`–`10`. 초(아래) 쪽 궁 줄이 랭크 1이다.
  - 내부 인덱스 `i = r*9 + c`에서 칸 이름은 `'abcdefghi'[c] + (10 - r)`.
  - 예: `a1`=81, `e2`=76, `e9`=13, `a10`=0.
  - Fairy-Stockfish의 장기 좌표와 같은 체계다.
- 수: `b1c3` 형식이고, 쉬기는 `pass`.
  - **Fairy-Stockfish는 쉬기를 궁이 제자리로 가는 수로 표기한다**(`e2e2`, `f10f10`, 실측). 엔진에서 받은 수나 PV에 이 형식이 있으면 `pass`로 바꾼다.
- 기물 글자: 초는 대문자, 한은 소문자. `K`궁 `R`차 `C`포 `H`마 `E`상 `A`사 `P`졸/병.
- FEN
  - 기물 글자 대응: `H→n`, `E→b`, 나머지는 같은 글자.
  - 초는 `w`, 한은 `b`.
  - 랭크 10부터 쓰고, 끝에 `- - 0 1`을 붙인다.
  - 초기 배치(양쪽 `마상상마`)는 Fairy-Stockfish `startFen`과 같다: `rnba1abnr/4k4/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/4K4/RNBA1ABNR w - - 0 1`

## 5. 게임 상태 기계 (`src/game.js`)

**편마다 컨트롤러**
- 1단계: `human | engine`
- 2단계: 여기에 `agent`가 추가된다.

**`engine` 차례일 때**
- 화면 계층이 420ms 뒤 `bestMove(level)`를 호출하고 그 수를 `game.play()`로 넣는다(원본과 같음).
- `game.js`는 타이머를 모른다.

**수가 반영된 뒤의 전이**: 원본 `step()`을 옮긴다.
- 둘 수 없고 장군이면 외통수로 끝나고 결과를 기록한다.
- 둘 수 없지만 장군이 아니면 자동으로 쉬고, 차례가 되돌아온다.
- 장군이면 메시지를 낸다.
- 메시지 말투는 원본을 따른다. 사람이 한 편뿐이면 "외통수! 이겼어요." 같은 원본 문구를 쓰고, 아니면 "외통수! 초(파랑) 승리" 같은 일반 문구를 쓴다.

**쉬기**: 장군이 아닐 때만 할 수 있다.

**무르기**
- 사람이 둘 차례인 국면이 나올 때까지 수를 되돌린다(최소 한 수). 사람 편이 없으면 비활성이다.
- 대기 중인 엔진 타이머는 화면 계층이 취소한다.

**API**: 모두 새 상태를 돌려주고, 입력은 바꾸지 않는다.
- `newGame({controllers, level, setups})`
- `play(state, move)`: 불법이면 이유가 담긴 에러를 던진다.
- `undo(state)`
- `legalMoves(state)`

## 6. 기보 (`src/record.js`, `src/storage.js`)

```json
{
  "v": 1,
  "id": "2026-09-28T14-03-12-345",
  "createdAt": "2026-09-28T14:03:12.345Z",
  "setups": { "c": "마상마상", "h": "상마상마" },
  "controllers": { "c": "human", "h": "engine" },
  "level": 3,
  "moves": ["b1c3", "h10g8", "pass"],
  "result": null,
  "analysis": {
    "engine": "fairy-stockfish-nnue.wasm 1.1.12 janggicasual nnue=janggi-9991472750de movetime=800",
    "evals": [ { "ply": 0, "cp": 12, "win": 51.1, "depth": 17 }, null ]
  }
}
```

`result`는 끝난 판이면 `{ "winner": "c", "reason": "외통수" }` 같은 값이 들어간다.

**정본은 수순이다**
- 국면은 `replay()`로 재구성한다.
- 엔진이 둔 수도 기록되므로 재생할 때 엔진을 다시 돌리지 않는다.
- 자동 쉬기는 국면이 결정하므로 수순에 넣지 않는다.
- `analysis`는 파생 캐시일 뿐이라, 없거나 깨져도 판은 복원된다.
- `evals[k]`는 k수 뒤 국면의 평가이고, 초 기준이다.

**저장**
- localStorage에 저장한다: 판 하나가 키 하나(`janggi.game.<id>`), 목록은 `janggi.index`.
- 수가 반영될 때마다, 그리고 분석 결과가 추가될 때마다 저장한다.
- 쓰기가 실패하면(용량 초과, 비공개 창 등) 대국은 계속한다. 대신 화면에 "기보 저장 실패 — 내보내기로 백업하세요"를 **명시적으로** 보여준다.

**복원**
- 페이지를 열면 가장 최근 판을 불러와 이어간다.
- 재생하다 불법 수가 나오면 그 판을 "손상됨"으로 표시하고 새 판을 시작한다. 손상된 기록은 지우지 않는다.

**내보내기와 가져오기**
- 내보내기는 판 하나 또는 전부를 JSON 파일로 저장한다.
- 가져오기는 `replay()`로 검증한 뒤 목록에 추가한다. 같은 id가 이미 있으면 새 id를 붙인다.

**id 형식**: `^[0-9T-]+(-[0-9]+)?$`. 가져올 때 검사한다.

## 7. 승률 분석

### 실측으로 확인한 것 (2026-09-28, M3 Max)

- **네이티브** brew 14.0.1 arm64로 잰 값:
  - 신경망이 적용된다.
  - 1스레드 800ms에서 depth 16–19, seldepth 20–28.
  - 800ms와 3초의 평가 차이는 승률 5%p 안쪽.
- **WASM** `fairy-stockfish-nnue.wasm` 1.1.12를 Node에서 잰 값:
  - `janggicasual` 규칙이 들어 있다.
  - `NNUE evaluation using /janggi-9991472750de.nnue enabled`가 나오고, 신경망을 끄면 평가가 달라진다(cp −1 vs 83).
  - 1스레드 800ms에서 depth 17, 초당 39만 국면(네이티브의 약 60%).
- **신경망 배달 (개정 2.1, 사용자 결정)**
  - Google Drive는 **브라우저 교차 출처 요청을 403으로 막는다.**
    - curl HEAD에 Origin만 붙이면 `access-control-allow-origin: *`를 준다.
    - 그런데 브라우저 헤더(`Sec-Fetch-*`와 Chrome UA)를 붙이면 403 HTML이 오고 CORS 헤더가 없다. Playwright에서도 `No 'Access-Control-Allow-Origin'`으로 실측했다.
    - 그래서 "Drive에서 직접 받기"는 폐기한다.
  - 라이선스가 불명확한 파일(2025년판, CC0 아님)을 **우리가 재배포하지 않는다.** 그래서 배포본에는 신경망이 없다.
  - **기본은 기본 평가(classical)다.** 화면에 "기본 평가(약함)"를 명시한다.
  - **"신경망 넣기"**
    - 사용자가 받아 둔 `.nnue` 파일을 고른다. 받는 곳 안내 링크는 `fairy-stockfish.github.io/nnue/`다.
    - 크기(11,261,920바이트)와 SHA-256(`9991472750de…`)을 검사한다.
    - 통과하면 Cache Storage에 저장하고, 엔진에 즉시 적용한다(`FS.writeFile`과 `EvalFile`).
    - 다음 방문부터는 캐시에서 자동으로 쓴다. "신경망 지우기"로 캐시를 비울 수 있다.
  - **dev 서버 편의**: `~/.janggi/`에 파일이 있으면 dev 서버에서만 같은 출처로 자동으로 쓴다. 빌드 산출물에서는 뺀다.
  - 만든 사람에게 재배포 허락을 받으면 "사이트에 같이 올리기"로 바꾼다.
- **규칙 차이**: `janggicasual`은 반복 국면을 무승부로, 연속 장군을 금지로 본다. 원본에는 이 규칙이 없다. FEN만 넘기므로 합법 수가 달라지지는 않는다. 다만 같은 수를 되풀이하는 국면에서는 승률이 50% 쪽으로 보일 수 있다.
- **아직 브라우저에서는 확인하지 않은 것**: GitHub Pages는 헤더를 설정할 수 없다(touchizen.com 응답에 COOP/COEP 없음). 그래서 `coi-serviceworker`로 교차 출처 격리를 켠다. 첫 방문에는 한 번 새로고침된다. 그 상태에서 Drive fetch(CORS 모드)가 통하는지는 구현할 때 Playwright로 확인한다.

### 로딩 (`src/analysis/`)

- `crossOriginIsolated`가 false면 분석을 끄고 "이 브라우저에서는 승률 분석을 쓸 수 없어요(교차 출처 격리 안 됨)"를 보여준다.
- 엔진은 `public/fsf/stockfish.js`를 로드해서 띄운다. 설정은 `UCI_Variant=janggicasual`, `Threads=1`, `MultiPV=5`.
- **신경망**
  - 신경망 출처는 이 순서로 찾는다: Cache Storage(사용자가 넣은 파일) → dev 전용 경로 → 없음(기본 평가).
  - 적용 여부는 엔진 출력에 `NNUE evaluation using … enabled`가 나오는지로 판정한다.
  - "신경망 넣기"에서 검사에 실패하면 이유를 보여주고, 캐시에 넣지 않는다.

### 대기열

- 수가 반영될 때마다 새 국면을 넣는다.
- **순서대로 하나도 건너뛰지 않고** `go movetime 800`으로 분석한다.
- 밀려 있으면 "분석 중 (n개 남음)"을 표시한다.
- 결과는 `{ply, cp|mate, win, depth, candidates[5]}`이다. UCI 점수는 두는 쪽 기준이라 초 기준으로 뒤집는다. 후보 수는 현재 국면용으로 메모리에만 둔다.
- 무르기, 새 판, 복기 판 전환이 들어오면 `stop`하고 무효가 된 항목을 버린다.
- 엔진이 죽거나 로딩에 실패하면 한 번 다시 띄운다. 또 실패하면 분석을 끄고 이유를 보여준다.

### 승률 (`src/winrate.js`)

- 초 승률 = `50 + 50·(2/(1+e^(−0.00368208·cp)) − 1)`. lichess의 체스 식이다.
  - 외통수 점수는 이기는 쪽 100, 지는 쪽 0으로 둔다.
  - **추정치다.** 화면 도움말에 "평가 점수를 체스 기준 식으로 바꾼 추정치"라고 적는다.
- 수마다 변화 = 둔 쪽 기준으로 (둔 뒤 − 두기 전). 자동 쉬기에는 등급을 매기지 않는다.
- 등급(둔 쪽 승률이 떨어진 폭):
  - 10%p 이상: `부정확 ?!`
  - 20%p 이상: `실수 ?`
  - 30%p 이상: `대실수 ??`

## 8. 복기

- "기보" 버튼을 누르면 목록이 최신순으로 나온다. 각 줄에는 날짜, 컨트롤러, 수 수, 결과가 보이고, 손상된 판은 표시가 붙는다. 여기서 내보내기와 가져오기도 한다.
- 한 판을 고르면 **복기 모드**로 들어간다.
  - 판은 읽기 전용이다. k수째 국면과 직전 수 강조를 보여준다.
  - 조작: `⏮ ◀ ▶ ⏭`, 키보드 `←` `→`, 번호 붙은 수순 목록(클릭하면 이동).
  - 수순 목록의 각 수 옆에 승률 변화와 등급을 붙인다.
  - **승률 그래프**: 판 전체 흐름을 보여준다. 클릭하면 그 수로 이동하고, 현재 수는 세로선으로 표시한다.
  - 분석이 빈 국면은 "분석하기"로 일괄 분석한다. 진행률을 보여주고 결과는 기보에 저장한다.
  - "대국으로 돌아가기" 버튼으로 나온다.
- 판 방향은 9절 규칙을 그 판의 컨트롤러에 적용한다.

## 12. 2단계 개요 — GCF MCP (상세 spec은 1단계 뒤에 따로)

- **서버**: 새 Firebase 프로젝트의 GCF(2세대)에 MCP Streamable HTTP 엔드포인트를 둔다. Claude Code, claude.ai 커넥터, ChatGPT 개발자 모드가 **고정 URL**로 붙는다.
- **판 코드**: 판마다 추측하기 어려운 코드를 준다(예: `K7Q2X9`). MCP 도구는 이 코드를 받는다. 코드가 그 판을 조작하는 열쇠다.
- **저장과 동기화**: 기보는 Firestore에 저장한다. 수 검증과 내장 엔진 응수는 GCF가 `src/game.js`와 `src/engine.js`를 그대로 써서 한다. 화면은 Firestore 실시간 구독으로 갱신한다.
- **도구**(1차 초안): `get_state`, `new_game`, `make_move {side, move}`(상대 응수까지 대기), `wait_for_turn`, `list_games`, `get_game`.
  - 대국 중인 판의 결과에는 승률을 넣지 않는다.
- **남용 대비**: 판 생성 속도 제한, 오래된 판 TTL.
- **승률**: 계속 보는 사람의 브라우저가 계산한다. 서버에서는 계산하지 않는다.
