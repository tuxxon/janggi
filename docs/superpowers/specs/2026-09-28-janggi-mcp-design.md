# 장기 — 실행 가능 앱 + MCP 대국 + 기보 복기 + 승률 분석 설계

날짜: 2026-09-28 · 상태: 설계 (구현 전)

## 1. 목표

1. `Janggi.jsx`(단일 파일, 프로젝트 없음)를 `npm start` 한 번으로 실행되는 앱으로 만든다.
2. MCP로 Claude(Claude Code 등)나 ChatGPT(개발자 모드 커넥터)가 **실제로 수를 둔다**.
3. 모든 대국을 **기보 파일**로 저장하고, 화면과 MCP 양쪽에서 **복기**할 수 있다.
4. Fairy-Stockfish로 국면을 분석해 **승률**을 보여준다. 표시 방식은 대국 중 막대, 수마다 변화와 실수 표시, 복기 그래프, 후보 수별 승률 네 가지다.

성공 기준:
- `npm start` 후 `http://localhost:8787`에서 대국이 된다.
- 헤드리스 `claude -p`가 MCP 도구만으로 엔진과 여러 수를 둔다(실측).
- 서버를 재시작해도 진행 중인 판이 이어지고, 지난 판을 한 수씩 되감아 볼 수 있다.
- 수를 둘 때마다 승률 막대가 갱신되고, 복기에서 승률 그래프와 실수 표시가 보인다.

## 2. 범위 밖

원본에 없던 규칙은 추가하지 않는다:
- 빅장, 점수(계가) 판정, 무승부/반복 규칙 — 원본처럼 외통수로만 승부.
- 여러 판 동시 진행 — 서버에는 진행 중인 판이 항상 하나.
- 인증 — 터널 URL을 아는 사람은 누구나 수를 둘 수 있다(게임 데이터뿐).
- 승률 보정 — 평가 점수를 승률로 바꾸는 식은 체스용 식을 그대로 쓴다. 장기 실전 통계로 맞추는 작업은 하지 않는다(11절).
- Fairy-Stockfish를 대국 상대(컨트롤러)로 쓰는 것 — 이번에는 분석 전용이다.

## 3. 구조: 서버가 판을 가진다

```
브라우저(React) ──REST(사람 수)──▶ ┐
       ▲                           │   Node 서버 (127.0.0.1:8787)
       └──SSE(상태·승률 푸시)───── ┤   ├─ Game (진행 중인 판 하나)
Claude Code ──HTTP /mcp──────────▶ ┤   ├─ 내장 엔진 자동 응수
ChatGPT ─cloudflared 터널─▶ /mcp ─▶ ┘   ├─ Analyzer ──UCI──▶ fairy-stockfish 프로세스
                                        └─ games/*.json (기보 + 분석 캐시)
```

진실은 서버의 판 하나뿐이다. 브라우저는 판을 그리기만 하는 뷰라서, 탭이 없어도 에이전트끼리 또는 에이전트와 엔진이 둘 수 있다.

기각한 안:
- **브라우저가 판을 가짐**: 탭이 열려 있어야만 AI가 둘 수 있고, 새로고침하면 판이 깨진다.
- **stdio MCP**: ChatGPT가 쓸 수 없다.

## 4. 좌표와 표기

- 칸: 파일 `a`–`i`(열 0–8), 랭크 `1`–`10`. 초(아래) 쪽 궁 줄이 랭크 1이다.
  - 내부 인덱스 `i = r*9 + c`에서 칸 이름은 `'abcdefghi'[c] + (10 - r)`.
  - 예: 초 왼쪽 차 `(9,0)` = `a1`, 초 궁 `(8,4)` = `e2`, 한 궁 `(1,4)` = `e9`.
  - Fairy-Stockfish의 장기 좌표와 같은 체계다. UCI 수를 따로 변환하지 않는다.
- 수: 출발 칸과 도착 칸을 붙여 쓴다(`b1c3`, `e4e5`, `a10a9`). 한 수 쉬기는 `pass`.
- 기물 글자: 초는 대문자, 한은 소문자. `K`궁 `R`차 `C`포 `H`마 `E`상 `A`사 `P`졸/병.
- FEN 변환(Fairy-Stockfish에 국면을 넘길 때만 쓴다):
  - 기물 글자 대응: `H→n`, `E→b`, 나머지는 같은 글자.
  - 초 = 백(`w`), 한 = 흑(`b`).
  - 랭크 10부터 1 순서로 쓴다.

## 5. 게임 상태 기계 (`server/game.js`)

- **편마다 컨트롤러**: 초·한 각각 `human | engine | agent`.
  - `human`: 브라우저 클릭/드래그로 둔다.
  - `engine`: 서버가 420ms 뒤 `bestMove(level)`로 자동으로 둔다. 원본의 지연을 유지한다. 여기서 엔진은 **원본 내장 엔진**이다.
  - `agent`: MCP `make_move`로 둔다.
- **수가 반영된 뒤의 전이**: 지금 React의 `step()`을 서버로 옮긴다.
  - 둘 수 없고 장군이면 외통수로 끝난다.
  - 둘 수 없지만 장군이 아니면 자동으로 쉬고 차례가 넘어간다.
  - 장군이면 메시지를 낸다.
  - 메시지의 말투는 원본을 따르되, 컨트롤러 조합에 맞게 일반화한다. 예: "외통수! 초(파랑) 승리".
- **쉬기**: 장군 상태가 아닐 때만 할 수 있다(원본 규칙).
- **무르기**: 브라우저에서만 할 수 있다.
  - 사람이 둘 차례인 국면이 나올 때까지 수를 되돌린다(최소 한 수). 원본의 "내 수와 AI 응수를 같이 무름"을 일반화한 것이다.
  - 사람 편이 없으면 무르기는 비활성이다.
  - 대기 중인 엔진 타이머는 취소하고, 무른 수 이후의 분석 결과는 버린다.
- **`waitForTurn(side, ms)`**: 판이 바뀔 때마다 조건을 다시 본다. 그 편 차례가 오거나, 판이 끝나거나, 시간이 넘으면 끝나고, 결과에 `timedOut` 여부를 싣는다.
- **엔진 탐색 부하**: 내장 엔진은 메인 스레드에서 동기로 돈다(원본 브라우저와 같음). 난이도 4에서 몇 초 동안 서버가 멈출 수 있다는 걸 받아들인다. Fairy-Stockfish는 별도 프로세스라 이 문제가 없다.

## 6. 기보 저장과 복원 (`server/store.js`, `src/record.js`)

한 판에 파일 하나. 경로는 `games/<id>.json`이고, id는 시작 시각에 밀리초까지 붙인 것이다(예: `2026-09-28T14-03-12-345`). `games/`는 git에서 제외한다.

```json
{
  "id": "2026-09-28T14-03-12-345",
  "createdAt": "2026-09-28T14:03:12.345Z",
  "setups": { "c": "마상마상", "h": "상마상마" },
  "controllers": { "c": "human", "h": "agent" },
  "level": 3,
  "moves": ["b1c3", "h10g8", "pass"],
  "result": null,
  "analysis": {
    "engine": "Fairy-Stockfish 14.0.1 janggicasual nnue=janggi-9991472750de movetime=800",
    "evals": [ { "ply": 0, "cp": 12, "win": 51.1, "depth": 17 }, null, { "ply": 2, "mate": 5, "win": 100, "depth": 21 } ]
  }
}
```

- `result`는 끝난 판이면 `{ "winner": "c", "reason": "외통수" }` 같은 값이 들어간다.
- `analysis`는 7절 참고.

**정본은 수순이다.** 국면은 저장하지 않고, 초기 배치에서 `replay()`로 재구성한다.
- 엔진이 둔 수도 수순에 기록되므로, 재생할 때 엔진을 다시 돌리지 않는다. 그래서 무작위성이 없다.
- 둘 수 없어서 생기는 자동 쉬기는 국면이 결정하므로, 재생하면 똑같이 다시 나온다. 수순에는 넣지 않는다.
- `analysis`는 수순에서 파생된 **캐시**일 뿐이다. 없거나 깨져도 판은 복원된다.

**쓰기**
- 수가 반영될 때마다 임시 파일에 쓰고 rename 한다. 쓰다가 죽어도 파일이 반쯤 깨지지 않는다.
- **파일 쓰기가 실패하면 그 수는 반영하지 않고 에러를 돌려준다.** 메모리와 파일이 어긋나지 않게 하기 위해서다.
- 분석 결과가 추가될 때도 같은 방식으로 쓴다. 분석 결과 쓰기가 실패하면 로그만 남긴다. 수는 이미 저장됐기 때문이다.

**무르기**: 무른 수는 수순에서 잘라내고, 그 뒤의 `evals`도 잘라낸다.

**서버 시작 시**
- 가장 최근 파일을 불러와 재생하고 그 판을 이어간다. 끝난 판이면 최종 국면을 보여준다. 파일이 하나도 없으면 새 판을 시작한다.
- 재생하다가 불법 수가 나오면(파일 깨짐) 조용히 넘어가지 않는다. 로그에 크게 남기고 새 판을 시작하며, 깨진 파일은 지우지 않는다.

**id 검증**: API로 들어온 id는 `^[0-9T-]+$`로 검사해서 경로 탈출(`../`)을 막는다.

## 7. 승률 분석 (Fairy-Stockfish)

### 엔진 확인 결과 (2026-09-28, 소스·배포 페이지 확인)

- Fairy-Stockfish는 장기를 지원한다. `src/variant.cpp`에 규칙 세트가 4개 있다:
  - `janggi`: 빅장 있음, 계가 있음
  - `janggitraditional`: 빅장 있음, 계가 없음
  - `janggimodern`: 빅장 없음, 계가 있음, 반복 수 금지
  - `janggicasual`: 빅장 없음, 계가 없음
- **`janggicasual`을 쓴다.** 원본처럼 빅장도 계가도 없다.
  - 남는 차이: 이 규칙 세트는 공통 규칙으로 **같은 국면이 반복되면 무승부**로 보고 **연속 장군 반복을 금지**한다(`nFoldValue = VALUE_DRAW`, `perpetualCheckIllegal = true`).
  - 원본에는 반복 규칙이 없다. 그래서 같은 수를 되풀이하는 국면에서는 승률이 50% 쪽으로 보일 수 있다. 분석에 넘기는 FEN에는 이전 수순이 없으므로, 반복 판정이 합법 수 자체를 바꾸지는 않는다.
- 장기 NNUE 신경망은 `janggi-9991472750de.nnue`(2025-07-31)다. 배포 페이지 기준으로 신경망 없이 두는 것보다 +1128 Elo 강하고, 최신 릴리스와 호환된다.
- 설치: `brew install fairy-stockfish`(14.0.1, 큰 판 빌드 포함). 이 맥은 arm64다. NNUE 내장 릴리스는 x86 전용이라 쓰지 않고, brew 바이너리에 `EvalFile`로 신경망을 넘긴다.
- 라이선스는 GPL-3.0이다. 코드에 섞지 않고 **별도 프로세스로 띄워 UCI로만 대화**한다. 바이너리와 신경망은 저장소에 넣지 않는다.

### 분석 방식 (`server/analyzer.js`)

- **엔진 설정**: 서버가 시작할 때 `fairy-stockfish` 프로세스를 하나 띄운다. 설정은 `UCI_Variant=janggicasual`, `EvalFile=<nnue 경로>`, `MultiPV=5`.
- **대기열**
  - 수가 반영될 때마다 새 국면을 대기열에 넣는다.
  - **국면을 순서대로 하나도 건너뛰지 않고** 각각 `go movetime 800`으로 분석한다. 수마다 승률 변화를 구하려면 모든 국면의 값이 필요하기 때문이다.
  - 수가 분석보다 빨리 쌓이면(엔진끼리 빠르게 두는 경우 등) 대기열이 밀린다. 화면은 분석이 끝난 가장 최근 값을 보여주면서 "분석 중 (n개 남음)"을 표시한다.
- **결과 처리**
  - 결과는 `{ply, cp | mate, win, depth, pv[] (후보 수 5개와 각 승률)}`다.
  - 기보 파일에는 `{ply, cp|mate, win, depth}`만 저장한다. 후보 수는 현재 국면용으로 메모리에만 둔다.
  - UCI 점수는 두는 쪽 기준이라 **초 기준으로 뒤집어서** 저장한다.
- **무르기와 새 판**: 무르기나 새 판이 들어오면 분석 중인 탐색을 `stop`하고, 무효가 된 대기열 항목을 버린다.
- **분석 시간**: 800ms는 실측하고 나서 조정한다. 판 수 곱하기 시간이 복기 일괄 분석 시간이 된다(예: 80수 판이면 약 65초).

### 승률 변환 (`src/winrate.js`)

- 초의 승률은 `50 + 50·(2/(1+e^(−0.00368208·cp)) − 1)`로 계산한다. lichess가 쓰는 체스 기준 식이다.
  - 외통수 점수는 이기는 쪽 100%, 지는 쪽 0%로 둔다.
  - **추정치다.** 장기 실전 통계로 보정하지 않았다. 큰 차이(70 대 90)는 믿을 만하지만 작은 차이(62 대 65)는 의미가 적다. 화면의 도움말에도 이렇게 적는다.
- **수마다 변화** = 둔 쪽 기준으로 (둔 뒤 승률 − 두기 전 승률).
  - 자동 쉬기는 수가 아니므로 등급을 매기지 않는다.
- **실수 등급**: 둔 쪽 승률이 떨어진 폭으로 매긴다. lichess 기준과 같다.
  - 10%p 이상: `부정확 ?!`
  - 20%p 이상: `실수 ?`
  - 30%p 이상: `대실수 ??`

### 엔진이 없을 때

- `fairy-stockfish`를 찾지 못하면 앱은 그대로 돌아가고 승률 기능만 꺼진다. 화면에 "Fairy-Stockfish가 없어 승률을 끔 — `npm run setup-engine`"을 **명시적으로** 보여준다.
- NNUE 파일이 없으면 기본 평가로 분석하되, 화면에 "NNUE 없음(약한 평가)" 표시를 붙인다. 조용히 약한 평가로 바꾸지 않는다.
- 엔진 프로세스가 죽으면 한 번 다시 띄운다. 또 죽으면 끄고, 이유를 화면에 보여준다.

### `setup-engine`

1. `fairy-stockfish`가 PATH에 없으면 `brew install fairy-stockfish`를 안내한다. 설치 자체는 사용자가 한다.
2. NNUE 파일을 `~/.janggi/janggi-9991472750de.nnue`로 받는다.
   - 크기는 11,261,920바이트(약 11MB)다.
   - 배포처는 Google Drive다(`https://drive.google.com/u/0/uc?id=1dAEzbK1rOm8UGm_-CLdDEgeopFDcAtQP&export=download`).
   - 2026-09-28에 HEAD 요청을 보내보니 확인 페이지 없이 `200 attachment`로 응답했다. 그래서 curl로 받을 수 있을 것으로 본다. 실제로 받는 것은 구현 첫 단계에서 확인한다.
   - 받은 파일은 크기와 SHA-256 해시로 검사한다(파일명의 해시와 대조).

## 8. 복기

### 화면

- "기보" 버튼을 누르면 저장된 판 목록이 최신순으로 나온다. 각 줄에는 날짜·시각, 초와 한의 컨트롤러, 수 수, 결과(승자 또는 진행 중)가 보인다.
- 한 판을 고르면 **복기 모드**로 들어간다.
  - 판은 읽기 전용이다. k수째 국면을 보여주고, 직전 수를 강조한다.
  - 조작: `⏮ ◀ ▶ ⏭` 버튼, 번호가 붙은 수순 목록(클릭하면 그 수로 이동), 키보드 `←` `→`.
  - **승률 그래프**: 판 전체의 초 승률 흐름을 선 그래프로 보여준다. 그래프를 클릭하면 그 수로 이동하고, 현재 수는 세로선으로 표시한다.
  - 수순 목록의 각 수 옆에 승률 변화(`+8` / `−25`)와 실수 등급(`?!` `?` `??`)을 붙인다.
  - 분석이 없는 국면이 있으면 "분석하기" 버튼으로 빈 국면만 일괄 분석한다. 진행률을 보여주고, 결과는 기보 파일에 저장된다.
  - 판 방향은 그 판의 컨트롤러 기준으로 정한다(9절 규칙과 같음).
  - "대국으로 돌아가기" 버튼으로 나온다. 진행 중인 판도 목록에 있어서 복기할 수 있다.
- 국면은 브라우저가 `src/record.js`의 `replay()`로 직접 계산한다. 서버는 기보 JSON만 준다.

### MCP

- `list_games`: 저장된 판 목록.
- `get_game {id, move?}`
  - 번호 붙은 수순을 주고, 끝난 판이면 수마다 승률과 실수 등급도 함께 준다.
  - `move`수째 국면의 ASCII 판을 준다(`move`를 생략하면 마지막 국면).
  - 에이전트가 "방금 판 복기해줘"에 답할 수 있게 하려는 것이다.

## 9. 화면 변경 (`src/Janggi.jsx`)

- 기존 렌더링과 조작(탭, 드래그, 슬라이드 애니메이션, 잡은 기물 트레이)은 그대로 둔다.
- 사람 편의 차례일 때만 입력을 받는다. 입력은 REST로 보낸다.
- 설정의 "AI가 둘 편"을 **초 / 한 각각 사람·엔진·AI 에이전트** 드롭다운으로 바꾼다. 난이도와 상차림 설정은 유지하고, 새 게임을 누를 때 적용된다(원본과 같음).
- 판 방향: 한이 사람이고 초가 사람이 아니면 뒤집는다.
- 상태 문구:
  - 엔진 차례: "엔진이 생각하는 중…"
  - 에이전트 차례: "AI 에이전트(MCP) 차례를 기다리는 중…"
- **승률 막대**: 판 위에 가로 막대로 "초 62% ▮▮▮▮▮▮▯▯▯▯ 38% 한"을 보여준다. 수마다 갱신하고, 분석이 밀려 있으면 "분석 중" 표시를 붙인다.
- **직전 수 평가**: 상태 줄 아래에 "초 b1c3 +3%p" 또는 "한 h10g8 −27%p 대실수 ??"를 보여준다.
- **후보 수 보기**: 토글로 켜고 끄며, 기본은 꺼짐이다. 훈수라서 원할 때만 보이게 한다.
  - 켜면 현재 국면의 상위 5수를 목록으로 보여준다(수와 두는 쪽 기준 승률).
  - 판 위에서는 각 수의 도착 칸에 작은 % 표시를 붙인다.
  - 켜져 있으면 에이전트끼리 두는 판을 구경할 때도 보인다. 에이전트는 화면을 보지 않으니 괜찮다.
- SSE가 끊기면 EventSource의 자동 재연결에 맡기고, 재연결되면 전체 상태를 다시 받는다.

## 10. REST / SSE

| 메서드 경로 | 용도 |
|---|---|
| `GET /api/state` | 현재 판 전체 상태 |
| `GET /api/events` | SSE. 판이나 분석이 바뀔 때마다 전체 상태를 보낸다 |
| `POST /api/move {from,to}` | 사람 수. 차례인 편이 `human`이 아니면 거부 |
| `POST /api/pass` | 사람의 쉬기 |
| `POST /api/undo` | 무르기 |
| `POST /api/new {cho,han,level,choSetup,hanSetup}` | 새 판 |
| `GET /api/games` | 기보 목록 |
| `GET /api/games/:id` | 기보 하나(분석 포함) |
| `POST /api/games/:id/analyze` | 빈 국면 일괄 분석 시작. 진행률은 SSE로 보낸다 |

상태 페이로드: `{id, b, turn, controllers, level, setups, last, caps, over, msg, moves, canUndo, engineThinking, analysis: {available, nnue, pending, current: {win, cp|mate, depth, candidates[]}, evals[]}}`

## 11. MCP 도구 (`/mcp`, Streamable HTTP, stateless)

| 도구 | 입력 | 동작 |
|---|---|---|
| `get_state` | — | ASCII 판, 차례, 편별 컨트롤러, 직전 수, 장군/외통수, 잡은 기물, 번호 붙은 수순, **차례인 편이 둘 수 있는 수 전체**(기물별로 묶음) |
| `new_game` | `cho, han`(각 `human\|engine\|agent`), `level?`, `cho_setup?`, `han_setup?` | 새 판을 시작하고 새 기보 파일을 만든다 |
| `make_move` | `side`(`cho\|han`), `move`(`b1c3` 또는 `pass`) | 검증 후 둔다. 그다음 **상대가 응수할 때까지 최대 25초 기다려** 결과 상태를 돌려준다 |
| `wait_for_turn` | `side`, `timeout_sec?`(기본 25, 최대 55) | 내 차례가 오거나 판이 끝날 때까지 기다린다 |
| `list_games` | — | 8절 |
| `get_game` | `id`, `move?` | 8절 |

**make_move 거부 조건**: 아래 경우에 거부하고, `isError`와 이유, 그리고 둘 수 있는 수 목록을 같이 돌려준다.
- `side`의 차례가 아닐 때
- 그 편이 `agent`가 아닐 때
- 둘 수 없는 수일 때
- 장군 상태에서 쉬려고 할 때

**side 파라미터**: Claude 대 ChatGPT처럼 에이전트 둘이 둘 때 서로의 편을 두지 않게 막는 장치다. 협조적인 클라이언트를 전제로 한다(인증 아님).

**승률은 대국 중인 에이전트에게 숨긴다** (사용자 결정):
- `get_state`, `make_move`, `wait_for_turn`의 결과에는 승률, 평가 점수, 후보 수를 넣지 않는다.
- `get_game`은 **지금 진행 중인 판이 끝나지 않았으면** 그 판의 승률을 빼고 준다. 끝난 판이나 지난 판은 승률까지 준다.
- 한계: REST `/api/state`는 사람 화면용이라 승률을 담는다. 에이전트가 MCP 밖에서 이 주소를 직접 부르면 볼 수 있다. 협조적인 클라이언트를 전제로 한다.

## 12. 보안

- `127.0.0.1`에만 바인드한다. CORS 헤더는 없다.
- **Host 헤더 검사**: `localhost`, `127.0.0.1`, `*.trycloudflare.com`만 허용한다. 악성 웹페이지가 DNS rebinding으로 로컬 서버를 조작하는 걸 막는다.
- 기보 id 형식을 검사한다(6절).
- Fairy-Stockfish에는 서버가 만든 FEN과 고정된 명령만 보낸다. 사용자 입력 문자열을 UCI에 그대로 넘기지 않는다.
- 터널을 열면 URL을 아는 누구나 둘 수 있다. 터널은 사용자가 `npm run tunnel`로 직접 열 때만 열린다.

## 13. 테스트 (TDD)

**vitest 단위 테스트**
- `notation`
  - 칸과 수 변환을 리터럴 값으로 확인한다(`a1`↔81, `e2`↔76, `e9`↔13 등).
  - 초기 배치의 FEN을 리터럴로 확인한다. 기준은 Fairy-Stockfish 소스의 `startFen`: `마상상마` 양쪽 = `rnba1abnr/4k4/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/4K4/RNBA1ABNR w`.
- `game`
  - 불법 수, 차례가 아닌 편, 컨트롤러 불일치를 거부하는지
  - 외통수, 자동 쉬기, 장군 중 쉬기 거부
  - 무르기 일반화
  - 엔진 자동 응수
  - `waitForTurn`이 끝나는 조건과 타임아웃
- `record`/`store`
  - 저장 → 새 인스턴스 → 복원했을 때 같은 국면이 되는지(자동 쉬기 포함)
  - 쓰기 실패 시 수를 거부하는지
  - 깨진 파일이면 새 판을 시작하고 파일은 남기는지
  - id 경로 탈출을 거부하는지
- `winrate`
  - 변환 식의 값(cp 0 → 50%, 외통수 → 100/0)
  - 두는 쪽 기준 뒤집기
  - 등급 경계(9.9%p / 10%p / 20%p / 30%p)
  - 자동 쉬기에는 등급을 매기지 않는지
- `analyzer`: 가짜 UCI 엔진(스크립트)으로 확인한다.
  - 국면을 순서대로 빠짐없이 분석하는지
  - 무르기나 새 판에서 `stop`하고 대기열을 버리는지
  - 엔진이 죽었을 때 재시작하고, 두 번째에는 끄는지
  - 엔진이 없을 때 명시적으로 표시하는지

**엔진 규칙 대조** (Fairy-Stockfish `janggicasual`, 설치돼 있을 때만 실행)
- 무작위 대국으로 수천 개 국면을 만들고, 국면마다 원본 엔진의 합법 수 집합과 Fairy-Stockfish의 `go perft 1` 결과를 대조한다. 쉬기 수는 대조에서 뺀다.
- 불일치가 나오면 **고치기 전에 사용자에게 보고**한다. 원본 엔진이 규칙을 틀렸을 수도 있기 때문이다.
- 대조에 쓴 국면 수와 결과는 리터럴로 박는다.

**MCP 통합 테스트**
- SDK 클라이언트로 HTTP 서버(임시 포트, 임시 `games/`)에 붙어 6개 도구를 전부 호출한다.
- 대국 중인 판에서는 어떤 도구 결과에도 승률이 없는지 확인한다.

**Playwright**
- 클릭으로 수를 두면 서버 상태가 바뀌는지
- MCP로 둔 수가 SSE를 타고 화면에 나오는지
- 승률 막대와 후보 수 토글
- 복기 이동과 승률 그래프
- 스크린샷을 눈으로 확인한다.

**실측 E2E**
- 헤드리스 `claude -p --mcp-config .mcp.json`이 엔진을 상대로 여러 수를 둔다.
- 실제 Fairy-Stockfish로 한 판을 분석해서 승률 흐름이 말이 되는지 본다.

**리뷰**: Codex(`gpt-6-astra` xhigh) 적대적 리뷰를 돌려서 HIGH/MED를 고친다.

## 14. 열린 결정 (이 설계에 포함하지 않음)

- **에이전트 보조 정보**: `get_state`에 "지금 공격받는 내 기물 / 지켜지지 않는 기물"을 넣을지. LLM이 기물을 공짜로 내주는 실수를 줄여주지만, 엔진의 추천 수를 주는 것은 아니다.
- **`preview_move`**: 가상의 수를 둔 뒤의 판과 상대가 따먹을 수 있는 수를 보여주는 도구. 에이전트가 머릿속에서 판을 옮기다 틀리는 문제를 없앤다. 승률은 넣지 않는다.
- **Fairy-Stockfish를 대국 상대로**: 컨트롤러에 추가할지.
