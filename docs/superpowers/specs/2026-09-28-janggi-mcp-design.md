# 장기 — 웹앱(Pages) + 승률 분석 + 기보 복기, 그리고 GCF MCP 대국 설계

날짜: 2026-09-28 · 개정 2.9 (더 깊이 보기: 분석 모드·여러 스레드·최강 3초) · 2.8 (상대가 쉬어도 반복수 셈이 끊김) · 2.7 (반복수: 같은 수 세 번째 금지, 궁·사 예외) · 2.6 (설정 패널 옆으로, 위/아래 나라 선택) · 2.5 (사람/엔진 즉시 적용) · 2.4 (리뷰 반영: WebKit 격리, 평가 보존, 최강 우선) · 2.3 (난이도 "최강" = Fairy-Stockfish) · 2.2 (두려는 수의 승률 추가) · 2.1 (신경망: 기본 평가 + 사용자가 넣기)

## 1. 단계

**1단계 — Pages 정적 웹앱** (이 문서에서 자세히 다룬다)
- 사람 대 사람, 사람 대 엔진, 엔진 대 엔진 대국
- 브라우저 안의 Fairy-Stockfish WASM으로 승률 분석
- 기보는 브라우저에 저장하고, 파일로 내보내고 가져올 수 있다. 복기 화면 포함
- 배포 주소는 `touchizen.com/janggi/`

**2단계 — GCF MCP 대국** (12절 개요만. 1단계가 끝난 뒤 상세 spec을 따로 쓴다)
- Claude와 ChatGPT가 고정 URL MCP로 두고, 판마다 코드로 구분한다.
- Firestore에 저장하고 실시간으로 동기화한다.

1단계 성공 기준:
- `npm run dev`로 로컬에서 대국, 승률, 복기가 된다. Playwright와 눈으로 확인한다.
- 실제 Chromium에서 `crossOriginIsolated === true`이고, 신경망으로 분석된 승률이 뜬다.
- Pages 배포본에서도 같은 것이 된다.

## 2. 범위 밖

원본에 없던 규칙은 추가하지 않는다:
- 빅장, 계가, 무승부/반복 규칙 — 원본처럼 외통수로만 승부.
- 승률 보정 — 평가 점수를 승률로 바꿀 때 체스용 식을 그대로 쓴다(7절).
- 1단계에서 AI 에이전트(MCP) — 2단계에서 한다.

## 3. 구조 (1단계)

```
touchizen.com/janggi/  (GitHub Pages, 정적)
 ├─ React 앱 ── src/game.js (상태 기계, 순수 함수) ── src/engine.js (원본 규칙·탐색)
 │     │
 │     ├─ src/analysis/ ── Fairy-Stockfish WASM (pthread, 자체 워커)
 │     │                    └─ NNUE: 사용자가 "신경망 넣기" → Cache Storage (없으면 기본 평가)
 │     └─ src/storage.js ── localStorage (기보) + JSON 내보내기/가져오기
 └─ coi-serviceworker.js ── COOP/COEP를 붙여 SharedArrayBuffer를 연다
```

`src/game.js`는 I/O가 없는 순수 모듈이다. 2단계 GCF가 **같은 파일을 그대로** 써서 수를 검증한다.

## 4. 좌표와 표기

- 칸: 파일 `a`–`i`(열 0–8), 랭크 `1`–`10`. 초(아래) 쪽 궁 줄이 랭크 1이다.
  - 내부 인덱스 `i = r*9 + c`에서 칸 이름은 `'abcdefghi'[c] + (10 - r)`.
  - 예: `a1`=81, `e2`=76, `e9`=13, `a10`=0.
  - Fairy-Stockfish의 장기 좌표와 같은 체계다.
- 수: `b1c3` 형식이고, 쉬기는 `pass`.
  - **Fairy-Stockfish는 쉬기를 궁이 제자리로 가는 수로 표기한다**(`e2e2`, `f10f10`, 실측). 엔진에서 받은 수나 PV에 이 형식이 있으면 `pass`로 바꾼다.
- 기물 글자: 초는 대문자, 한은 소문자. `K`궁 `R`차 `C`포 `H`마 `E`상 `A`사 `P`졸/병.
- FEN
  - 기물 글자 대응: `H→n`, `E→b`, 나머지는 같은 글자.
  - 초는 `w`, 한은 `b`.
  - 랭크 10부터 쓰고, 끝에 `- - 0 1`을 붙인다.
  - 초기 배치(양쪽 `마상상마`)는 Fairy-Stockfish `startFen`과 같다: `rnba1abnr/4k4/1c5c1/p1p1p1p1p/9/9/P1P1P1P1P/1C5C1/4K4/RNBA1ABNR w - - 0 1`

## 5. 게임 상태 기계 (`src/game.js`)

**편마다 컨트롤러**
- 1단계: `human | engine`
- 2단계: 여기에 `agent`가 추가된다.

**`engine` 차례일 때**
- 화면 계층이 420ms 뒤 `bestMove(level)`를 호출하고 그 수를 `game.play()`로 넣는다(원본과 같음).
- `game.js`는 타이머를 모른다.

**수가 반영된 뒤의 전이**: 원본 `step()`을 옮긴다.
- 둘 수 없고 장군이면 외통수로 끝나고 결과를 기록한다.
- 둘 수 없지만 장군이 아니면 자동으로 쉬고, 차례가 되돌아온다.
- 장군이면 메시지를 낸다.
- 메시지 말투는 원본을 따른다. 사람이 한 편뿐이면 "외통수! 이겼어요." 같은 원본 문구를 쓰고, 아니면 "외통수! 초(파랑) 승리" 같은 일반 문구를 쓴다.

**난이도 "최강"** (개정 2.3, 사용자 결정)
- 난이도 목록은 쉬움(2)·보통(3)·어려움(4)·**최강**이다. 앞의 셋은 원본 엔진 `bestMove(level)` 그대로다.
- **최강은 Fairy-Stockfish가 둔다.** 설정은 `janggicasual`, `go movetime 3000`(개정 2.9, 원래 1000), MultiPV 1이고, `Skill Level`을 낮추지 않는다. 엔진이 보기에 **승률이 가장 높은 수(`bestmove`)를 항상** 둔다.
  - 쉬기 표기(`e2e2`)는 `pass`로 바꾼다. 받은 수는 `game.play`로 검증한다. 불법이면 에러로 멈추고, 원본 엔진으로 조용히 바꾸지 않는다.
  - 그 탐색 결과는 그 국면의 분석으로도 쓴다. 승률 막대와 `evals`에 들어가므로 같은 국면을 두 번 분석하지 않는다.
  - 신경망이 있으면 NNUE로, 없으면 기본 평가로 둔다. 상태 표시에 어느 쪽인지 적는다.
- 교차 출처 격리가 안 되거나 엔진 로딩에 실패하면 "최강"을 비활성으로 두고 이유를 보여준다. **약한 엔진으로 조용히 대체하지 않는다.** 저장된 판이 최강인데 엔진을 쓸 수 없으면, 엔진 차례에서 멈추고 이유를 보여준다.

**반복수** (개정 2.7, 사용자 요청: "카카오 장기 규칙을 따르면 돼", "궁과 사는 무한 반복수 가능")
- **근거**: 카카오 장기의 공식 규칙 문서는 찾지 못했다. 그래서 카카오 호환을 목표로 만든 Fairy-Stockfish `janggimodern`의 `moveRepetitionIllegal` 구현(`src/position.cpp`)을 줄 단위로 따라가 기준으로 삼았다. 대한장기연맹 규정 7조("만년장/반복수: 3회까지 허용하며 4회 반복하면 실격패")는 세부 조건이 없어 참고만 했다.
- **규칙**: 궁·사가 아닌 한 기물로 **같은 수를 세 번째 둘 수 없다**. 반칙패가 아니라 그 수를 둘 수 없게 막는다.
  - 판정: 내 수 5개가 한 기물의 두 칸 왕복이고, 첫 수가 그 출발점에 도착한 수이면 다섯 번째 수를 막는다.
  - 예: 초 차 a1a2, a2a1, a1a2, a2a1 다음의 a1a2.
  - 다른 기물로 들어온 경우(c4c5, a1a2, a2a1, a1a2)에는 다음 a2a1이 두 번째라 허용된다.
- **셈이 끊기는 경우**
  - 그 사이 어느 쪽이든 기물을 잡음
  - 장군을 받은 상태에서 둔 수(지금 포함)
  - **어느 쪽이든 쉬기**
    - 자동 쉬기도 포함한다. 자동 쉬기는 기록에 안 남으므로 "같은 편이 연달아 둔 두 수"로 알아본다.
    - 내 쉬기: FSF는 직전 쉬기를 건너뛰고 세지만, 여기서는 끊는 것으로 단순화했다.
    - 상대 쉬기(개정 2.8, 사용자 요청 "상대방이 한 수 쉬면, 우린 둘 수 있는 거거든"): FSF는 세지 않지만 사용자 규칙을 따른다.
    - 내 자동 쉬기를 끊지 않으면 막힌 수뿐인 쪽이 끝없이 묶인다(리뷰에서 발견).
- **적용 범위**: 새 판부터 적용한다(기보의 `repetition: true`). 표시가 없는 옛 기보는 규칙 없이 두어진 그대로 재생한다.
- **엔진**
  - 원본 엔진(쉬움~어려움): 막힌 수가 있으면 그 수를 뺀 루트 탐색을 한다. `engineMove.js`가 원본 `bestMove`와 같은 식이다. 막힌 수가 없으면 원본 그대로 둔다.
  - 분석·최강(Fairy-Stockfish): FEN만 받아 수순을 모르므로, 막힌 수가 있는 국면은 `searchmoves`로 루트 수를 제한한다. 쉬기는 궁 제자리 표기로 넣는다. 트리 안쪽의 반복은 엔진이 모른다.
- **화면**: 기물을 집으면 막힌 칸에 ✕를 표시한다. 그 칸을 누르면 "반복수: 같은 수를 세 번째 둘 수 없어요."를 보여준다.
- **범위 밖**: 동형반복(서로 다른 기물로 같은 국면 반복)과 만년장 전체 규칙.

**쉬기**: 장군이 아닐 때만 할 수 있다.

**무르기**
- 사람이 둘 차례인 국면이 나올 때까지 수를 되돌린다(최소 한 수). 사람 편이 없으면 비활성이다.
- 대기 중인 엔진 타이머는 화면 계층이 취소한다.

**API**: 모두 새 상태를 돌려주고, 입력은 바꾸지 않는다.
- `newGame({controllers, level, setups, bottom = "c", repetition = true})`
- `play(state, move)`: 불법이면 이유가 담긴 에러를 던진다.
- `undo(state)`
- `legalMoves(state)`

## 6. 기보 (`src/record.js`, `src/storage.js`)

```json
{
  "v": 1,
  "id": "2026-09-28T14-03-12-345",
  "createdAt": "2026-09-28T14:03:12.345Z",
  "setups": { "c": "마상마상", "h": "상마상마" },
  "controllers": { "c": "human", "h": "engine" },
  "level": 3,
  "bottom": "c",
  "repetition": true,
  "moves": ["b1c3", "h10g8", "pass"],
  "result": null,
  "analysis": {
    "engine": "fairy-stockfish-nnue.wasm 1.1.12 janggicasual nnue=janggi-9991472750de mode=continuous movetime=800 deepen-movetime=20000 max-movetime=3000 threads=7",
    "evals": [ { "ply": 0, "cp": 12, "win": 51.1, "depth": 17 }, null ]
  }
}
```

`result`는 끝난 판이면 `{ "winner": "c", "reason": "외통수" }` 같은 값이 들어간다.

**정본은 수순이다**
- 국면은 `replay()`로 재구성한다.
- 엔진이 둔 수도 기록되므로 재생할 때 엔진을 다시 돌리지 않는다.
- 자동 쉬기는 국면이 결정하므로 수순에 넣지 않는다.
- `analysis`는 파생 캐시일 뿐이라, 없거나 깨져도 판은 복원된다.
- `evals[k]`는 k수 뒤 국면의 평가이고, 초 기준이다.

**저장**
- localStorage에 저장한다: 판 하나가 키 하나(`janggi.game.<id>`), 목록은 `janggi.index`.
- 수가 반영될 때마다, 그리고 분석 결과가 추가될 때마다 저장한다.
- 쓰기가 실패하면(용량 초과, 비공개 창 등) 대국은 계속한다. 대신 화면에 "기보 저장 실패 — 내보내기로 백업하세요"를 **명시적으로** 보여준다.

**복원**
- 페이지를 열면 가장 최근 판을 불러와 이어간다.
- 재생하다 불법 수가 나오면 그 판을 "손상됨"으로 표시하고 새 판을 시작한다. 손상된 기록은 지우지 않는다.

**내보내기와 가져오기**
- 내보내기는 판 하나 또는 전부를 JSON 파일로 저장한다.
- 가져오기는 `replay()`로 검증한 뒤 목록에 추가한다. 같은 id가 이미 있으면 새 id를 붙인다.

**id 형식**: `^[0-9T-]+(-[0-9]+)?$`. 가져올 때 검사한다.

## 7. 승률 분석

### 실측으로 확인한 것 (2026-09-28, M3 Max)

- **네이티브** brew 14.0.1 arm64로 잰 값:
  - 신경망이 적용된다.
  - 1스레드 800ms에서 depth 16–19, seldepth 20–28.
  - 800ms와 3초의 평가 차이는 승률 5%p 안쪽.
- **WASM** `fairy-stockfish-nnue.wasm` 1.1.12를 Node에서 잰 값:
  - `janggicasual` 규칙이 들어 있다.
  - `NNUE evaluation using /janggi-9991472750de.nnue enabled`가 나오고, 신경망을 끄면 평가가 달라진다(cp −1 vs 83).
  - 1스레드 800ms에서 depth 17, 초당 39만 국면(네이티브의 약 60%).
- **신경망 배달 (개정 2.1, 사용자 결정)**
  - Google Drive는 **브라우저 교차 출처 요청을 403으로 막는다.**
    - curl HEAD에 Origin만 붙이면 `access-control-allow-origin: *`를 준다.
    - 그런데 브라우저 헤더(`Sec-Fetch-*`와 Chrome UA)를 붙이면 403 HTML이 오고 CORS 헤더가 없다. Playwright에서도 `No 'Access-Control-Allow-Origin'`으로 실측했다.
    - 그래서 "Drive에서 직접 받기"는 폐기한다.
  - 라이선스가 불명확한 파일(2025년판, CC0 아님)을 **우리가 재배포하지 않는다.** 그래서 배포본에는 신경망이 없다.
  - **기본은 기본 평가(classical)다.** 화면에 "기본 평가(약함)"를 명시한다.
  - **"신경망 넣기"**
    - 사용자가 받아 둔 `.nnue` 파일을 고른다. 받는 곳 안내 링크는 `fairy-stockfish.github.io/nnue/`다.
    - 크기(11,261,920바이트)와 SHA-256(`9991472750de…`)을 검사한다.
    - 통과하면 Cache Storage에 저장하고, 엔진에 즉시 적용한다(`FS.writeFile`과 `EvalFile`).
    - 다음 방문부터는 캐시에서 자동으로 쓴다. "신경망 지우기"로 캐시를 비울 수 있다.
  - **dev 서버 편의**: `~/.janggi/`에 파일이 있으면 dev 서버에서만 같은 출처로 자동으로 쓴다. 빌드 산출물에서는 뺀다.
  - 만든 사람에게 재배포 허락을 받으면 "사이트에 같이 올리기"로 바꾼다.
- **규칙 차이**: `janggicasual`은 반복 국면을 무승부로, 연속 장군을 금지로 본다. 원본에는 이 규칙이 없다. FEN만 넘기므로 합법 수가 달라지지는 않는다. 다만 같은 수를 되풀이하는 국면에서는 승률이 50% 쪽으로 보일 수 있다.
- **교차 출처 격리**: GitHub Pages는 헤더를 설정할 수 없다(touchizen.com 응답에 COOP/COEP 없음). 그래서 `coi-serviceworker`로 켠다. 첫 방문에는 한 번 새로고침된다. 헤더 없는 `vite preview`에서 `crossOriginIsolated === true`와 WASM 분석을 Playwright로 실측했다(마일스톤 0).

### 격리와 WebKit (리뷰 뒤 실측, 2026-09-28)

- **vite preview는 `server.headers`를 물려받는다.** 그래서 마일스톤 0부터 "헤더 없는 preview로 Pages 조건을 재현했다"는 검증이 실제로는 서비스워커 경로를 한 번도 타지 않았다.
  - `preview.headers: {}`로 비웠다.
  - smoke 테스트가 "preview 응답에 COOP/COEP가 없다"를 단언한다.
- **coi-serviceworker 0.1.7은 WebKit에 `credentialless`를 준다.**
  - 이 정책에서 WebKit(Playwright WebKit 26.6)은 엔진의 pthread 워커(`stockfish.worker.js`)를 COEP 위반으로 막는다.
  - 그래서 `index.html`에서 `coepCredentialless: () => false`로 모든 브라우저에 `require-corp`를 쓰게 했다. 앱에는 다른 출처의 하위 리소스가 없다.
- **coi-serviceworker의 fetch 처리기는 304 응답에서 죽는다.** 원 저장소 master도 같은 코드다.
  - WebKit은 캐시된 워커 스크립트에 조건부 요청을 보낸다. 그러면 `new Response(body, {status: 304})`가 TypeError를 던져서 워커가 뜨지 않는다.
  - 수정본을 `vendor/coi-serviceworker.js`에 두고 배포한다(MIT, 수정 표시). 수정 내용: 304는 캐시 없이 다시 받고, 204·205는 본문 없이 만든다.
  - WebKit e2e 프로젝트(`@webkit`)가 이것을 지킨다. 수정 전에는 4번 중 4번 실패했고, 수정 후에는 3번 중 3번 통과했다.

### 로딩 (`src/analysis/`)

- `crossOriginIsolated`가 false면 분석을 끄고 "이 브라우저에서는 승률 분석을 쓸 수 없어요(교차 출처 격리 안 됨)"를 보여준다.
- 엔진은 `public/fsf/stockfish.js`를 로드해서 띄운다. 설정은 `UCI_Variant=janggicasual`, `MultiPV=5`, `Hash=64`, `Threads = clamp(floor(navigator.hardwareConcurrency / 2), 1, 8)`(개정 2.9, 원래 1).
- **신경망**
  - 신경망 출처는 이 순서로 찾는다: Cache Storage(사용자가 넣은 파일) → dev 전용 경로 → 없음(기본 평가).
  - 적용 여부는 엔진 출력에 `NNUE evaluation using … enabled`가 나오는지로 판정한다.
  - "신경망 넣기"에서 검사에 실패하면 이유를 보여주고, 캐시에 넣지 않는다.

### 대기열

- 수가 반영될 때마다 새 국면을 넣는다.
- **순서대로 하나도 건너뛰지 않고** 분석 모드의 시간(빠르게·계속 800ms, 깊게 3000ms)으로 분석한다.
- 밀려 있으면 "분석 중 (n개 남음)"을 표시한다.
- 결과는 `{ply, cp|mate, win, depth, candidates[5]}`이다. UCI 점수는 두는 쪽 기준이라 초 기준으로 뒤집는다. 후보 수는 현재 국면용으로 메모리에만 둔다.
- 무르기, 새 판, 복기 판 전환이 들어오면 `stop`하고 무효가 된 항목을 버린다.
- **초점 분석**(두려는 수의 승률)
  - 방식: `setoption MultiPV <n>`을 준 뒤 `go movetime 500 searchmoves <그 기물의 합법 수 n개>`. 각 수의 점수는 두는 쪽 기준이고, 승률로 바꿔서 칸에 붙인다.
  - 우선순위는 **국면 분석이 먼저**다. 막대와 수마다 변화에 필요하므로, 그 국면의 분석이 끝난 뒤에 돈다.
  - 다른 기물을 집거나, 선택을 풀거나, 수가 둬지면 진행 중인 초점 분석을 `stop`하고 결과를 버린다.
  - 실측(2026-09-28, 네이티브, 중반 국면)
    - 국면의 모든 수를 MultiPV로 한 번에 분석하면 800ms에 depth 10에 그친다.
    - `searchmoves`로 한 기물(차)의 수만 분석하면 600ms에 depth 14다. 결과는 h1h3 +51cp(55%), h1h2 +25cp(52%), h1i1 −1044cp(2%).
    - 그래서 초점 방식을 쓴다. WASM은 네이티브의 약 60% 속도다.
- 엔진이 죽거나 로딩에 실패하면 한 번 다시 띄운다. 또 실패하면 분석을 끄고 이유를 보여준다.
  - 감시 타이머: 탐색 하나가 `movetime + 15초` 안에 `bestmove`를 내지 않으면 실패로 본다.

### 분석 모드 — 더 깊이 보기 (개정 2.9, 사용자 결정 2026-09-29: 네 가지 전부)

- 설정 패널의 **"분석"**: 빠르게(0.8초) / 깊게(3초) / **계속**(기본). 보기 설정이라 고르는 즉시 적용하고 `localStorage["janggi.prefs"]`에 기억한다.
- **계속**: 0.8초 결과를 먼저 보여주고, 할 일이 없으면 보고 있는 국면을 `go movetime 20000`으로 계속 깊게 읽는다.
  - 보고 있는 국면: 대국이면 마지막 국면, 복기면 k수째(`service.deepen(k)`, 대국으로 돌아오면 `deepen(null)`).
  - 우선순위: 최강 > 밀린 국면(순서대로) > 초점 분석 > 깊게 보기. **최강 차례 국면은 깊게 보지 않는다**(그 탐색이 곧 엔진의 수다).
  - 선점: 판이 바뀌거나(새 수 포함), 초점 분석 요청, 계속이 아닌 모드로 바꿈, 다른 국면으로 `deepen`, 신경망 교체, 종료가 오면 `stop`한다. 같은 국면으로 다시 동기화하는 것은 선점하지 않는다.
  - **점진 결과**: 엔진은 반복마다 1~N순위를 한 묶음으로 찍는다. 묶음의 마지막 순위 줄이 왔을 때, 1순위가 지금 보여준 결과보다 깊을 때만 결과로 보낸다. 1순위 줄에서 바로 보내면 이전 반복의 아래 순위와 섞여 후보가 하나 빠진다(실측: 표본 180개 중 73개가 4개). 선점 뒤 다시 시작한 얕은 탐색은 표시를 되돌리지 않는다.
  - 20초 상한까지 다 읽은 국면은 다시 깊게 보지 않는다. 모드를 바꾸거나 신경망을 바꾸면 다시 허용한다.
  - 승률 막대 설명에 "깊이 N · 계속 분석 중"을 보여준다.
- 기보의 `analysis.engine`에 모드, 탐색 시간, 최강 시간, 스레드 수를 적는다. 평가 병합 로직은 그대로다.
- 실측 근거(M3 Max, Chromium WASM, NNUE, 초반/중반 depth): MultiPV 5·1스레드·0.8초 11/13 → 4스레드·0.8초 12/15 → 8스레드·3초 17/20 → MultiPV 1·4스레드·3초 16/28.

### 승률 (`src/winrate.js`)

- 초 승률 = `50 + 50·(2/(1+e^(−0.00368208·cp)) − 1)`. lichess의 체스 식이다.
  - 외통수 점수는 이기는 쪽 100, 지는 쪽 0으로 둔다.
  - **추정치다.** 화면 도움말에 "평가 점수를 체스 기준 식으로 바꾼 추정치"라고 적는다.
- 수마다 변화 = 둔 쪽 기준으로 (둔 뒤 − 두기 전). 자동 쉬기에는 등급을 매기지 않는다.
- 등급(둔 쪽 승률이 떨어진 폭):
  - 10%p 이상: `부정확 ?!`
  - 20%p 이상: `실수 ?`
  - 30%p 이상: `대실수 ??`

## 8. 복기

- "기보" 버튼을 누르면 목록이 최신순으로 나온다. 각 줄에는 날짜, 컨트롤러, 수 수, 결과가 보이고, 손상된 판은 표시가 붙는다. 여기서 내보내기와 가져오기도 한다.
- 한 판을 고르면 **복기 모드**로 들어간다.
  - 판은 읽기 전용이다. k수째 국면과 직전 수 강조를 보여준다.
  - 조작: `⏮ ◀ ▶ ⏭`, 키보드 `←` `→`, 번호 붙은 수순 목록(클릭하면 이동).
  - 수순 목록과 직전 수 평가 줄은 한글 기물 이름으로 적는다: "3. 초 졸 c4→c5 −35%p 대실수 ??", "한 마 h10→g8 −7%p"(사용자 결정 2026-09-29). 후보 수와 같은 `describeMove`를 쓴다.
  - 수순 목록의 각 수 옆에 승률 변화와 등급을 붙인다.
  - **승률 그래프**: 판 전체 흐름을 보여준다. 클릭하면 그 수로 이동하고, 현재 수는 세로선으로 표시한다.
  - (구현 결정) 복기에 들어가면 **평가가 빈 국면만 자동으로 분석**한다. "분석하기" 버튼은 두지 않는다.
    - 진행률은 승률 막대의 "분석 중 (n개 남음)"으로 보여준다.
    - 결과는 그 판의 기보에 저장하되, 목록 순서(가장 최근 판)는 바꾸지 않는다.
  - 복기하는 동안 진행 중인 대국은 멈춘다. 엔진 차례를 미루는 것이다. 최강 엔진이 복기 판의 분석을 자기 수로 착각하지 않게 하기 위해서다.
  - 기보에 평가가 이미 있는 지난 국면은 다시 분석하지 않는다. 새로고침한 뒤나 복기할 때 해당된다. 현재 국면은 후보 수와 최강 수가 필요해서 항상 분석한다.
  - "대국으로 돌아가기" 버튼으로 나온다.
- 판 방향은 그 기보의 `bottom`(아래쪽 나라)을 따른다. 없으면 옛 규칙을 쓴다(9절).

## 9. 화면 (`src/Janggi.jsx`)

- 기존 렌더링과 조작(탭, 드래그, 슬라이드, 잡은 기물 트레이)은 그대로 둔다.
- 설정의 "AI가 둘 편"을 **초 / 한 각각 사람·엔진** 드롭다운으로 바꾼다. 2단계에서 "AI 에이전트"가 추가된다.
  - (개정 2.5, 사용자 요청) **사람/엔진은 고르는 즉시 지금 판에 적용한다.** 사람으로 바꾼 편은 기다리고, 엔진으로 바꾼 편은 제 차례면 바로 둔다. 원래는 새 게임을 눌러야 반영돼서 선택 상자와 실제 판이 어긋났다.
  - 무르기를 해도 지금 고른 설정을 유지한다. 과거 국면의 설정으로 되돌리지 않는다.
  - 최강에서 엔진으로 바꾸면 그 국면을 최강 탐색(1초, MultiPV 1)으로 다시 한다.
  - 난이도(쉬움·보통·어려움·**최강**)와 상차림은 새 게임을 누를 때 적용된다.
- (개정 2.6, 사용자 요청) **설정 패널을 판 옆으로 옮긴다.**
  - 넓은 화면에서는 판 오른쪽에 두고, 좁은 화면에서는 판 아래에 둔다.
  - 복기 중에는 그 자리에 복기 조작이 온다.
- **위/아래 자리마다 나라·두는 이·상차림을 고른다.**
  - 나라는 연동된다. 한쪽을 한나라로 하면 다른 쪽은 초나라가 된다.
  - 두는 이와 상차림은 자리에 붙는다. 아래가 사람이면 아래 나라를 바꿔도 아래는 사람이다.
  - 나라·상차림·난이도는 새 게임부터 적용하고, "새 게임부터 적용: …"으로 알린다. 두는 이와 분석 모드(개정 2.9)는 즉시 적용한다.
- **판 방향은 아래쪽 나라(`bottom`)를 따르고, 기보에 저장한다.** 방향이 없는 옛 기보는 예전 규칙을 쓴다(한만 사람이면 한이 아래).
- 선수는 방향과 상관없이 항상 초다.
- **승률 막대**: 판 위에 "초 62% ▮▮▮▮▮▮▯▯▯▯ 38% 한". 분석 중 표시와 NNUE 상태 표시를 붙인다.
- **직전 수 평가**: "한 h10g8 −27%p 대실수 ??".
- **후보 수 보기**(훈수 모드): 토글이고 기본은 꺼짐이다. 켜면 두 가지가 보인다.
  1. 현재 국면의 상위 5수 목록(수와 두는 쪽 기준 승률). 판 위 도착 칸에 % 표시를 붙인다.
  2. **두려는 수의 승률** (개정 2.2, 사용자 요청)
     - 기물을 탭하면 이동 가능한 칸에 점이 뜬다(기존과 같음).
     - 약 0.5초 뒤 **각 점 위에 "그 수를 두면 두는 쪽 승률"**이 뜬다. 예: 55% / 52% / 2%.
     - 색은 지금 국면 승률 대비 변화로 정한다. 등급 기준은 7절과 같다.
       - 떨어진 폭이 10%p 미만이면 초록
       - `?!` 노랑
       - `?` 주황
       - `??` 빨강
     - 드래그 중에 칸 위에 올리면 그 칸의 숫자를 크게 보여준다.
     - 복기 모드에서도 같다. k수째 국면에서 기물을 집으면 보인다.
- 폰 폭(360px)에서도 가로 스크롤이 없어야 한다. 원본이 `maxWidth 560` 반응형이라 그 구조를 유지한다.

  - touchizen.github.io에 커스텀 도메인 `touchizen.com`이 있으므로, 프로젝트 사이트는 `touchizen.com/janggi/`로 뜰 것으로 본다. 배포할 때 확인한다.
- **GPL 준수**
  - 저장소 전체를 GPL-3.0으로 한다.
  - 배포본에 `fsf/Copying.txt`를 포함한다.
  - 화면 하단에 "승률 분석: Fairy-Stockfish (GPL-3.0) · 소스"와 링크(`github.com/fairy-stockfish/fairy-stockfish.wasm`, 이 앱 저장소)를 둔다.
- 신경망은 배포본에 넣지 않는다(재배포하지 않음). 사용자가 "신경망 넣기"로 직접 넣는다.

## 11. 테스트 (TDD)

**vitest**
- `notation`: 칸, 수, FEN을 리터럴 값으로 확인한다. `startFen`과 일치하는지, 쉬기 변환(`e2e2`→`pass`)도 본다.
- `game`
  - 불법 수 거부, 외통수, 자동 쉬기, 장군 중 쉬기 거부
  - 무르기 일반화(사람/엔진 조합별)
  - 메시지 문구
- `record`
  - `replay()`: 자동 쉬기를 포함해서 재현하는지, 손상된 기록을 검출하는지
  - 가져오기 검증, id 형식
- `storage`
  - 저장 → 불러오기 왕복
  - 쓰기 실패 시 명시적 상태로 바뀌는지(localStorage가 예외를 던지게 해서)
- `winrate`
  - 식의 값(cp 0 → 50%, 외통수 → 100/0)
  - 기준 뒤집기, 등급 경계(9.9 / 10 / 20 / 30), 자동 쉬기 제외
- `analysis`: 가짜 UCI 엔진으로 확인한다.
  - 대기열 순서, 건너뛰지 않는지
  - `stop`과 무효화
  - 쉬기 변환
  - NNUE 판정 줄이 없으면 "약한 평가" 상태가 되는지
  - 재시작 1회
- **규칙 대조**
  - WASM Fairy-Stockfish를 Node에서 돌려서(`fetch` 제거 우회, 실측) 무작위 대국 국면 수천 개를 만든다.
  - 국면마다 원본 엔진의 합법 수 집합과 `go perft 1`을 대조한다(쉬기 제외).
  - 불일치가 나오면 **고치기 전에 사용자에게 보고**한다. 대조 국면 수와 결과는 리터럴로 박는다.

**Playwright** (로컬, `vite build` + `vite preview`)
- 서비스워커가 격리를 켰는지(`crossOriginIsolated === true`)
- 기본 평가 상태 표시, 그리고 "신경망 넣기"(`setInputFiles`로 로컬 `.nnue`)를 하면 NNUE 적용 표시로 바뀌는지. 새로고침 뒤 캐시에서 유지되는지. 잘못된 파일은 거부하는지
- 클릭으로 수를 두고 엔진이 응수하는지, 무르기
- 새로고침 뒤 판이 복원되는지
- 복기 이동, 그래프, 내보내기/가져오기
- 360px 폭에서 가로 스크롤이 없는지
- 스크린샷을 **눈으로 확인**한다.

**배포 확인**: 실제 `touchizen.com/janggi/`(또는 이전 전 주소)에서 같은 것을 확인한다.

## 12. 2단계 개요 — GCF MCP (상세 spec은 1단계 뒤에 따로)

- **서버**: 새 Firebase 프로젝트의 GCF(2세대)에 MCP Streamable HTTP 엔드포인트를 둔다. Claude Code, claude.ai 커넥터, ChatGPT 개발자 모드가 **고정 URL**로 붙는다.
- **판 코드**: 판마다 추측하기 어려운 코드를 준다(예: `K7Q2X9`). MCP 도구는 이 코드를 받는다. 코드가 그 판을 조작하는 열쇠다.
- **저장과 동기화**: 기보는 Firestore에 저장한다. 수 검증과 내장 엔진 응수는 GCF가 `src/game.js`와 `src/engine.js`를 그대로 써서 한다. 화면은 Firestore 실시간 구독으로 갱신한다.
- **도구**(1차 초안): `get_state`, `new_game`, `make_move {side, move}`(상대 응수까지 대기), `wait_for_turn`, `list_games`, `get_game`.
  - 대국 중인 판의 결과에는 승률을 넣지 않는다.
- **남용 대비**: 판 생성 속도 제한, 오래된 판 TTL.
- **승률**: 계속 보는 사람의 브라우저가 계산한다. 서버에서는 계산하지 않는다.
